Consistência entre fontes

Estar no ar não basta: a resposta também precisa estar certa. Quando duas APIs publicam o mesmo dado, as duas são comparadas campo a campo, ignorando acentos e maiúsculas. Quando uma fonte não responde, a comparação fica inconclusiva e não conta como divergência.

Incidentes recentes

Como funciona

Operacional
Respondeu na primeira tentativa, em menos de 3 s, com um conteúdo que passa na validação. Não basta o HTTP 200: se o CEP da UFPA voltar sem a UF “PA”, conta como falha.
Lento
A resposta foi útil, mas só depois de uma nova tentativa ou acima de 3 s.
Fora do ar
Erro de rede, tempo esgotado (10 s), erro HTTP ou conteúdo inválido depois de até 3 tentativas com backoff exponencial.

As verificações rodam no GitHub Actions, a partir de servidores nos EUA. A latência inclui a viagem até o Brasil e serve para comparar tendências, não para medir a experiência de quem está no país. O agendamento do GitHub pode atrasar alguns minutos em horários de pico.

Construído sobre duas bibliotecas próprias: resilient-api-client (timeout, retry com backoff e jitter) e reconciliation-report (comparação chaveada entre fontes). Os dados brutos ficam em data/status.json.
