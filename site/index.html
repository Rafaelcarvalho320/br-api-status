Conferência entre fontes

Responder não basta: a resposta também precisa estar certa. Quando duas APIs publicam o mesmo dado, os campos são comparados um a um, sem diferenciar acento nem maiúscula. Se uma fonte não responde, a comparação fica inconclusiva e não conta como divergência.

Incidentes recentes

Como a verificação funciona

Operando
Respondeu na primeira tentativa, em menos de 3 s, com um conteúdo que passa na validação. HTTP 200 sozinho não basta: se o CEP da UFPA voltar sem a UF “PA”, a verificação falha.
Lento
A resposta veio certa, mas só depois de uma nova tentativa ou acima de 3 s.
Fora do ar
Erro de rede, tempo esgotado (10 s), erro HTTP ou conteúdo inválido depois de até 3 tentativas com backoff exponencial.

As verificações rodam no GitHub Actions, a partir de servidores nos EUA. A latência inclui a viagem até o Brasil, então serve para comparar tendências, não para medir a experiência de quem está no país. O agendamento do GitHub pode atrasar alguns minutos em horários de pico.

A página usa duas bibliotecas minhas: resilient-api-client (timeout, retry com backoff e jitter) e reconciliation-report (comparação chaveada entre fontes). Os dados brutos estão em data/status.json.
